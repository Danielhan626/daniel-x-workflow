# X Post Recipes

These are compositional choices, not fill-in-the-blank text to copy literally. Pick the smallest set of components that carries the idea.

| Input or goal | Preferred shape | Components to consider | Check |
| --- | --- | --- | --- |
| One observation or judgment | Single post | Specific opening -> claim -> example or reason -> implication | One idea; readable without a link |
| How-to or decision rule | Single post or short thread | Result -> steps or criteria -> boundary | Reader can actually use it |
| Project update or case | Single post or thread | Problem -> action -> observed result -> next decision | State what is verified and what is pending |
| New tool or trend | Single post or thread | What changed -> tested/public evidence -> who benefits -> limitation | Date and source are current |
| Existing article | Single post, thread, or Article | Extract one thesis -> reframe for X -> select proof -> link only if useful | No copied WeChat sign-off or filler |
| Response to another post | Reply or quote post | Identify the exact claim -> add agreement, counterexample, or missing condition -> useful consequence | Original context preserved |
| Chart, image, or video | Media post | Visual claim -> what to notice -> why it matters | Asset matches claim; alt text if supported |

## Component Library

- **Opening:** a concrete result, contradiction, question, or reader problem. Earn attention without claiming guaranteed outcomes.
- **Claim:** one sentence that says what Daniel thinks or recommends.
- **Evidence:** an observed example, project artifact, verifiable source, or clearly labeled inference. Avoid unsupported numbers.
- **Mechanism:** the short causal explanation that makes the claim useful.
- **Action:** one step, checklist, decision rule, or question the reader can answer. A CTA is optional.
- **Boundary:** who this does not fit, what remains untested, or what would change the conclusion.

## Format Notes

### Single post

Start with the point. Use line breaks to separate thought units, not to make every sentence a dramatic fragment. Prefer one insight over a list of unrelated tips. A link can support the claim, but the post should still say something useful on its own.

### Thread

Use a thread only when each additional post adds evidence, a step, a counterpoint, or a conclusion. Keep the sequence obvious. The opener promises a specific payoff; middle posts deliver it; the ending summarizes the decision or next step. Do not force a fixed post count or add a recap that repeats the opener.

### Quote post or reply

Read the referenced post and its immediate context. Name the point being answered accurately. Add a concrete example, caveat, or question; avoid paraphrasing the original as if it were Daniel's insight.

### X Article

Use for a genuinely deep argument or guide when the editor is available to the active account. A normal X post may introduce or link to it. Verify formatting, images, links, and preview in the actual editor before publication.

## Review Pass

Read the post aloud once. Remove any sentence that repeats the claim without new evidence or reader value. Check that a skeptical reader can distinguish Daniel's experience from public information and uncertainty. For browser-ready or live publication, inspect the exact copy and media in X's composer, since its limits and account features can change.
